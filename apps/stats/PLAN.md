# Plan: Statistics learning app — `apps/stats` (@kiwari/stats)

## Context

The user wants an app to learn Introductory Statistics (OpenStax 2e) section by section: interactive quizzes with auto-grading, teaching of the concept behind each mistake, a mistake log with a "review until understood" loop, and a printable paper-test mode that can produce a fresh, different test on demand. User decisions: new workspace app in this monorepo; curated bank + parameterized templates with Claude optional; mixed question formats; **server-side** storage (assumed: name-based learner profiles, no password, JSON files behind a swappable store interface).

## Design principles

- **Content is data, generated by a committed ingestion script.** The app never touches the network for content. `apps/stats/scripts/ingest_openstax.py` (the working parser from this session, moved into the repo) downloads the CNXML and emits per-chapter JSON under `apps/stats/content/openstax/`; the Try It docx and lecture-notes text are converted by the same script from local copies checked into `apps/stats/content/sources/` (both CC BY 4.0). Generated JSON is committed so `npm install && npm run dev:stats` works offline.
- **Three question layers**, all keyed to the 58 OpenStax sections and to concept tags:
  1. **Auto-gradable source items**: MC (options + letter answer), numeric (solution parses as a number / short list of numbers), true/false, fill-in symbol. Derived mechanically by a classifier plus a small hand-curated override file.
  2. **Self-assessed source items** (`kind: 'open'`): free-response with a model solution. The learner answers in a textbox, then sees the model solution and marks "I got it / I missed it". Misses enter the mistake log like any other. This is how the ~1,000 solved free-response items become usable without discarding them.
  3. **Parameterized templates** (hand-written TS, ~2–4 per numeric section): fresh numbers every seed, deterministic explanation with substituted values. These make "new test with different questions" unbounded, not just a reshuffle.
- **Pure TS + pure functions** for catalog, bank loading, PRNG, grading, test building, mastery reducer. Server owns only persistence and optional Claude. Mirrors apps/web (engine = pure, web = glue).
- **Deterministic**: `(scope, id, seed)` → identical test; template instances carry their seed in the id (`ci-mean-z#123456`).
- **Event-sourced progress**: client POSTs `answer`/`finish` events; the server reducer re-grades auto-gradable items itself and trusts the learner's self-assessment only for `open` items.
- **Claude optional**, copying `apps/web/src/lib/ai/interpreter.ts`: `hasApiKey()` guard → fallback; try/catch → fallback; `messages.parse` + `zodOutputFormat`; LLM output passes the same `validateQuestion()` as authored content. Used for (a) fresh question variants, (b) richer explanations, (c) optional grading assist on `open` items (compare learner text vs model solution → suggestion, learner still confirms).

## Ingestion pipeline (`scripts/ingest_openstax.py`, ported from `scratchpad/osbooks/extract.py`)

1. Fetch manifest + collection + 102 modules from raw.githubusercontent.com (skip if cached under `scripts/.cache/`).
2. Parse CNXML → text: MathML to plain unicode (`mfrac`→`a/b`, `msqrt`→`√( )`, `mover` bar→`x̄`), lists to `a.`/`b.` lines, tables to `[TABLE] … [/TABLE]` blocks (rendered as real tables by `QuestionStem`), figures to `[FIGURE: caption]`. Un-comment `<!-- <solution> -->` blocks.
3. Per section: Try Its (from `note.class="statistics try"`), `practice`, `free-response` (homework), `bring-together-*`, `summary`, `formula-review`, glossary. Keep `context` paragraphs/tables ("Use the following information…") attached to each exercise.
4. Practice tests / finals / review exercises: numbered `<para>` items, solutions matched by number test-wide; sections tagged by the nearest "N.N:" heading (finals have none → tagged by classifier keyword rules + overrides).
5. Merge Try It solutions from the docx by chapter + text similarity (>0.6), else `overrides.json`.
6. Split lecture notes by `CHAPTER N:` / `N. Title` headings → `content/notes/chNN.json`, mapped to section ids (notes' Ch1 §3 "Organizing Categorical and Quantitative Data" → 1.3; Ch7 §4 "Stats Lab" dropped; Ch13 §2 "Testing Standard Deviations" → 13.4; Chebyshev appendix → 2.7 extra).
7. Classify each solved item into a `Question` kind:
   - `mc` when `options` exist and solution starts with a letter (`d`, `c. 4/16`) → `correctIndex`.
   - `numeric` when the solution is one number (optionally with `%`, `$`, units) → `answer` + tolerance from the decimals shown (abs = 0.6 × 10⁻ᵈ, min 0.005).
   - `fill` for hypothesis-symbol items (`H0: μ __ 45` patterns, answers `=,≠,<,>,≤,≥`).
   - `tf` when solution ∈ {true,false,yes,no} and the stem is a yes/no question.
   - `open` otherwise (has a model solution). Items with no solution, or graph-only solutions (`[FIGURE]`), are excluded from quizzes but kept in the JSON.
   - Emits `content/openstax/index.json` with counts per section per kind; the `content.test.ts` thresholds read from it.
8. Emit `ATTRIBUTION.md` and a `sources.json` with fetch date, commit SHA of the OpenStax repo, and license strings.
9. **Extra-sources importer** (`scripts/ingest_extra.py`, same classifier): reads `content/sources/extra/*.txt|pdf` (PDF via `pypdf`) and per-file front-matter (`source`, `license`, `chapters`, `format`). Formats: `exam-mc` (De Anza: `N.` stems, `A.`–`D.` options possibly on one line, "Questions X–Y refer to the following" contexts, "Form A / Form B" key table on the last page) and `pressbooks-practice` (VT Extra Practice: numbered exercises with answers/solutions blocks). Emits `content/extra/<source>.json` with the same `Question` shape and `sectionId` assigned by chapter + keyword rules + `overrides.json`.

## Data model (`src/lib/types.ts`)

- `Question` base `{ id, sectionId, conceptTag, stem, context?, table?, explanation: string[], source: 'openstax'|'tryit'|'template'|'llm', sourceRef: { module?, exerciseId?, test?, n? }, difficulty? }` ∪ kind:
  `mc { options, correctIndex }` · `numeric { answer, tolerance:{abs?,rel?}, unit? }` · `fill { blanks:[{label, answer, accept?}], symbolSet? }` · `tf { answer }` · `open { modelSolution: string, rubric?: string[] }`.
- `Given` per kind (`open` → `{ text, selfMark?: 'got'|'missed' }`); `GradeResult { correct, correctDisplay, perBlank?, needsSelfMark? }`.
- `Template { id, sectionId, conceptTag, kind, generate(rng) }`; `instantiate(t, seed)`.
- `TeachSnippet { sectionId, title, notesText, summary, formulas[], keyTerms[], steps?, byTag? }`.
- `TestSpec { scope:'section'|'chapter'|'practice-test'|'final', id, count, seed, mix: { openShare, templateShare } }`, `Test`.
- `QuestionRef` = `{openstax,id}` | `{template, templateId, seed}` | `{llm, snapshot}`.
- `Profile`, `Attempt`, `MistakeEntry`, `ConceptReview { streak, required: 2, status }`, `Mastery`, `ProfileView`, `ProgressEvent` (`answer` | `selfmark` | `finish`).

Grading (`grade.ts`, shared): MC index; numeric parse (`-3.67`, `3,200`, `3/8`, `35%`, `$12.84`) with abs/rel tolerance; fill symbol normalization (`>=`→`≥`, `mu`→`μ`, `phat`→`p̂`, case/space-insensitive, `accept[]`); tf; `open` → `needsSelfMark` until a `selfmark` arrives.

Mastery (`progress.ts`): wrong or "missed" → `MistakeEntry` + `review[tag] = open`; two consecutive correct on that tag → `understood`; section `mastered` when last quiz score ≥ 0.8 and no open concept in it.

## Test generation (`rng.ts`, `testgen.ts`)

- `mulberry32`, FNV-1a `hashString`, Fisher–Yates shuffle, `pick` returning `T`.
- `buildTest(spec)`: seeded from `"scope:id:seed"`; per-section quotas; fill from templates (`templateShare`), auto-gradable source items, then `open` items up to `openShare` (default 0.3 in quizzes, 0.5 in print); no repeats; shuffle; `shuffleOptions` for MC with remapped `correctIndex`. Scope `practice-test`/`final` reproduces an OpenStax test verbatim (for print) or samples from it.
- `buildReviewSet(profile, n, seed)`: per open concept prefer a template → another item with that tag → the missed item itself.

## Server storage and API

- `LearnerStore { list, get, findByName, create, update(id, fn), remove }`; `JsonFileStore(dir)` writes `data/profiles/<id>.json` atomically with a per-id promise chain; `getStore()` reads `STATS_DATA_DIR ?? cwd/data`.
- Routes on the `apps/web/src/app/api/interpret/route.ts` template: `GET /api/health`, `GET/POST /api/profiles`, `GET/DELETE /api/profiles/[id]`, `POST /api/profiles/[id]/events` (zod-validated; reducer re-grades), `POST /api/generate`, `POST /api/explain`, `POST /api/assess` (open-item grading assist; fallback returns `null` so the UI just shows the model solution).
- Client `store.ts` + `actions.ts` mirror `apps/web/src/lib/actions.ts` (`post<T>()`), profile id remembered in `localStorage['stats-profile']`.

## Risks / notes

- `noUncheckedIndexedAccess` is on; Next 15 dynamic-route `params` are Promises; keep `content/` and `src/lib` free of Node imports.
- Classifier precision: review `index.json` counts per kind after milestone 1 and spot-check 5 sections; corrections go in `overrides.json`, never in generated files.
- Numeric tolerance from displayed decimals can be too tight for rounding-table differences (z-tables vs calculator); allow `rel: 0.01` on probabilities.
- Final-exam items have no section tag in the source; classifier keyword rules + overrides assign them.
- Python is used for the ingest script only (stdlib, no deps); the app itself stays pure TS.
